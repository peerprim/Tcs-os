# Product Philosophy — Default First

Life OS is a preconfigured tracking system.

The user should be able to open the application and start using it immediately, without designing their own organizational structure.

**The loop:** Input → Track → Observe → Progress → Modify.

**Not:** Configure → Organize → Customize everything → Eventually start using it.

## Default configuration

The application provides:

- Default rooms.
- Default activities.
- Default recurring intervals.
- Default categories and tags.
- Default condition scales.
- Default point values.

### Rooms are dynamic

Defaults: Kitchen, Bedroom, Bathroom, Living room.

Users can add, rename and remove rooms, and move activities and items between them. The default structure is already there on first launch.

### Activities are ready to use

Each room ships with the trackers that belong in it. The bathroom comes with cleaning trackers. The bedroom comes with bedsheets and laundry trackers.

Users can adjust frequency, add activities or remove irrelevant ones. Nobody should have to create every tracker by hand.

## User modification

Everything should be adjustable where appropriate:

- Add, remove and rename rooms.
- Modify activities.
- Change recurrence intervals.
- Add custom items and lists.
- Change tags and categories.
- Adjust point values and preferences.

## Core philosophy

The system does the organizational work. The user primarily provides input, completes activities and observes their progression.

Customization is optional, not a prerequisite.

**Guardrail:** don't let customization become another form of procrastination. The defaults must be good enough that someone can start tracking their life within minutes.

## The app tracks reality

Life OS shouldn't only show completed tasks. It should show the condition of your life over time, so the user sees patterns rather than checkboxes.

| Activity   | Current state | Time overdue |
| ---------- | ------------- | ------------ |
| Vacuuming  | 3/5           | 5 days       |
| Laundry    | 4/5           | 8 days       |
| Bedsheets  | 2/5           | 2 days       |
| Dishes     | 1/5           | Not overdue  |

## Future intelligence

AI is an enhancement, not a dependency. The application must be fully functional without it.

Eventually, AI may analyze historical data to:

- Identify recurring patterns.
- Suggest activities that have been neglected.
- Recommend small improvements.
- Suggest random activities to break routines.
- Generate challenges based on historical behaviour.

Examples:

> "You've spent most of your time maintaining your apartment this week. Try something creative today."

> "You haven't done anything outside your usual routine lately. Here's a random challenge."

## Summary

The product should be:

- Useful without AI.
- Useful without customization.
- Increasingly valuable through consistent use.
